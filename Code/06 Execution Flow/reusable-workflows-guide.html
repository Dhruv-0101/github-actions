GitHub Actions: Reusable Workflows Guide

Inputs aur Outputs ko dynamic scope ke through target file tak bubble-up karne ka pure logic, simple Hinglish explanation ke saath.

Sections

Inputs Flow

📥 Caller se Reusable tak Arguments pass karna

Maan lo aapke paas ek build artifact folder hai (e.g. `dist-files`). Aapko is folder ka naam reusable workflow me pass karna hai. Dekho kaise parameters transfer hote hain step-by-step:

1

Caller sends argument

use-reuse.yml file ke with: block me value specify ki jati hai.

artifact-name: dist-files
▼
2

Reusable receives parameters

reusable.yml ke top configuration on workflow_call.inputs me variable receive hota hai.

inputs.artifact-name
▼
3

Step consumes parameter

Steps ke andhar is dynamically variable ko load karke download script chalai jati hai.

${{ inputs.artifact-name }}

💡 Inputs ka Feel (Hinglish Analogy)

Ye bilkul normal program function calling ki tarah hai:

"Caller file ne function call kiya: reusableDeploy('dist-files'). Reusable file ne function definition likhi: function reusableDeploy(artifactName). Pura code chalte samay jahan bhi artifactName tha, wahan automatic 'dist-files' replacement ho gaya."

Outputs Flow

📤 Outputs Bubble-Up Chain

Ek Reusable Job ke steps ek unique VM ke inside run hote hain. Job complete hote hi wo VM delete ho jati hai. Value ko bubble-up karke caller file tak laane ka 4-stage pipeline is tarah hai:

1

Step Level (Save to local notepad)

Step apna run execute karne ke baad $GITHUB_OUTPUT stream file me string variable save karta hai.

step-result=success
▼
2

Job Level (Save to job border)

Job ke exit-gate outputs block me steps ke data ko retrieve karke job output banaya jata hai.

outcome: ${{ steps.set-result... }}
▼
3

Workflow Level (Save to public API)

Workflow ke top level workflow_call.outputs me mapping connection configure kiya jata hai.

result: value: ${{ jobs.deploy... }}
▼
4

Caller reads Return Value

Caller workflow needs.deploy.outputs.result tag call karke use log print ya script run me print karta hai.

${{ needs.deploy.outputs.result }}

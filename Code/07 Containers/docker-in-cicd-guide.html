Avatar 1 · The Side-Car Assistant

🗄️ Avatar 1: Docker as a Helper / Temporary Database (`services:`)

Soch: "Mera code Express/Node.js mein hai. Main integration tests chalana chahta hoon, jisme MongoDB ya Redis se data read/write karna padega. Par main AWS cloud pe real database kholkar paise kharch nahi karna chahta!"

🍳 Kitchen & Fridge Analogy
Runner VM ek Kitchen hai aur tumhara code wahan ka Chef hai jo platform par khada hokar khana paka raha hai (`npm ci`, `npm test`).
services: mongodb kitchen ke kone mein rakha hua ek Fridge hai! Chef fridge ke andar jaake nahi baithta — Chef bahar kitchen platform par hi rehta hai aur fridge se saman lene ke liye 127.0.0.1:27017 pe connection banata hai!
02 Finished Project/.github/workflows/deploy.yml (Services Example)
jobs:
  test:
    runs-on: ubuntu-latest   # 🖥️ Tumhara test code Host Ubuntu VM pe chalega!
    env:
      MONGODB_CONNECTION_PROTOCOL: mongodb
      MONGODB_CLUSTER_ADDRESS: 127.0.0.1:27017  # 👈 Localhost port!
      MONGODB_USERNAME: root
      MONGODB_PASSWORD: example
    services:                # 🐳 Docker helper container background me chalu hoga!
      mongodb:
        image: mongo
        ports:
          - 27017:27017      # Host ke 27017 port se bind kar diya!
        env:
          MONGO_INITDB_ROOT_USERNAME: root
          MONGO_INITDB_ROOT_PASSWORD: example
    steps:
      - uses: actions/checkout@v3
      - run: npm ci
      - run: npm start & npx wait-on http://127.0.0.1:8080
      - run: npm test          # ⚡ Super fast local tests!
Kaun Chal Raha Hai Container Mein?

Sirf aur sirf MongoDB engine! Tumhara Node.js code, Playwright tests, aur `npm ci` host Ubuntu VM par chal rahe hain.

Kab Use Karna Hai?

Integration testing ke waqt jab app ko databases (MongoDB, Postgres, MySQL) ya Caches (Redis, Memcached) chahiye hon.

Fayda

Zero cloud cost, microsecond query speed, zero test collision, aur job end hote hi container auto-delete!

Avatar 2 · The Execution Environment

📦 Avatar 2: Docker as a Clean Room (`container:`)

Soch: "GitHub ke Ubuntu runner par pata nahi kaunsa Node version ya GCC compiler pada hai. Meri app strictly Node 16 + Alpine Linux par hi compile hoti hai. Main chahta hoon meri poori pipeline ek isolated container ke andar baith kar chale!"

🔬 Laboratory Clean-Room Analogy
Yahan tum Chef ko kitchen platform par khula nahi chhodte — tum Chef ko ek Sealed Clean-Room Laboratory Cabin (`node:16`) ke andar bitha dete ho!
Ab Chef jo bhi kaam karega (`checkout`, `npm ci`, `npm test`), wo sab usi sealed cabin ke andar hoga. Bahar ki Ubuntu VM se uska koi lena-dena nahi!
Job-Level Container Example
jobs:
  build-and-test:
    runs-on: ubuntu-latest
    container:
      image: node:16-alpine     # 👈 MAGIC! Poora job is container ke andar chala gaya!
    steps:
      - uses: actions/checkout@v4  # Code container ke workspace me aayega
      - name: Check Node version
        run: node -v               # ✨ Guaranteed v16.x.x (jo image me hai!)
      - run: npm ci
      - run: npm test
Kaun Chal Raha Hai Container Mein?

Tumhari POORI pipeline ke steps! `actions/checkout`, `npm ci`, `npm test` sab `node:16-alpine` container ke process context mein execute hote hain.

Kab Use Karna Hai?

Jab app ko legacy runtime (jaise Node 12 ya Python 3.7) chahiye, ya specific Linux distro (Alpine, CentOS, Debian) ki jarurat ho jo GitHub runner par pre-installed nahi hai.

🚨 Networking Trap Yaad Rakhna!

Agar job mein `container:` bhi hai aur `services:` bhi, toh service ko `127.0.0.1` se connect mat karna — service ke naam se connect karna: `mongodb:27017` (kyunki dono same Docker bridge network pe hote hain!).

Avatar 3 · The Shippable Artifact

🚀 Avatar 3: Docker as the Final Product (Build & Push)

Soch: "Mere tests pass ho gaye. Ab mujhe meri app production par deploy karni hai. Production server (AWS ECS / Kubernetes / Cloud Run) code files nahi maangta — wo bolta hai: 'Mujhe Docker image do, main usse chala dunga!'"

📦 Factory Packaging Analogy
Factory (GitHub Runner) mein car ke saare parts check ho gaye (`test` pass).
Ab factory us car ko ek sealed shipping container mein pack karti hai (`docker build`), us container par barcode/tag lagati hai (`v1.0.0`), aur global ship warehouse (Docker Hub / AWS ECR / GHCR) par bhej deti hai (`docker push`)!
Production CI/CD: Docker Build & Push
jobs:
  build-and-push:
    runs-on: ubuntu-latest
    permissions:
      packages: write   # GHCR registry pe push karne ki permission!
    steps:
      - uses: actions/checkout@v4

      - name: Login to GitHub Container Registry
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and Push Docker Image
        uses: docker/build-push-action@v5
        with:
          context: .                   # Uses tumhara Dockerfile!
          push: true
          tags: ghcr.io/${{ github.repository }}:latest
Kaun Chal Raha Hai Container Mein?

Abhi koi container run nahi ho raha! Yahan Runner VM sirf Docker CLI ka use karke ek Image FILE create aur upload kar raha hai, taaki production servers use baad mein chala sakein!

Kab Use Karna Hai?

Release / Deployment pipeline mein jab code `main` branch pe merge ho aur naya version live cloud par deploy karna ho.

Avatar 4 · The Self-Contained Custom Tool

🧩 Avatar 4: Docker as a Custom Action (Type 3 Action)

Soch: "Yaad karo Section 08 ka `deploy-s3-docker`! Humne AWS S3 pe deployment script Python aur `boto3` mein likhi thi. Hum chahte the ki jo bhi developer ye action call kare, use runner par Python install na karni pade — action apna Python environment khud jeb mein leke aaye!"

08 Custom Actions/.github/actions/deploy-s3-docker/action.yml
name: 'Deploy to AWS S3'
inputs:
  bucket: { required: true }
runs:
  using: 'docker'
  image: 'Dockerfile'  # 👈 Docker container sirf is ek step ko run karega!
Kaun Chal Raha Hai Container Mein?

Sirf wahi ek specific Step! Runner ne action ka Dockerfile chala kar Python script execute ki, S3 pe upload kiya, output `$GITHUB_OUTPUT` mein likha, aur step khatam hote hi container delete ho gaya!

Kab Use Karna Hai?

Jab kisi custom logic ke liye Go, Rust, Python, ya specific Linux binaries chahiye jo runner VM pe maujood nahi hain.

🎯 Test Karo — Kitna Clear Hua?

Har question ka answer click karke check karo. Instant Hinglish explanation milegi!

1. Agar tumne workflow mein services: redis: image: redis lagaya, toh kya tumhara npm test step Redis container ke andar chalega?
2. Tum chahte ho ki tumhare workflow steps strictly golang:1.21-alpine ke andar execute hon taaki runner VM ki Go version ka koi asar na ho. Kaunsa avatar use karoge?
3. Tumhare workflow mein container: image: node:16 aur services: mongodb: image: mongo dono lage hain. Node.js app ko MongoDB se connect karne ke liye kya address use karna chahiye?
4. Tests pass hone ke baad production Kubernetes cluster pe live deploy karne ke liye Docker ka kaunsa use-case chalta hai?
5. Ek Python deployment script ko bina runner par Python install kiye ek reusable step block ki tarah chalane ke liye kya use hota hai?
